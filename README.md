# Solo Leveling App

Технічна документація мобільного додатку для відстеження щоденних активностей та звичок, побудованого за принципами гейміфікації на основі концепції рольових систем (RPG).

---

## 1. Загальний огляд

**Solo Leveling App** — нативний Android-додаток, розроблений для автоматизації та структурування щоденних задач користувача. Застосунок трансформує рутинні активності у формат щоденних квестів із системою нарахування досвіду, підвищення рівнів, присвоєння рангів і штрафних санкцій за невиконання встановлених цілей.

### Ключові функціональні модулі
- **Система щоденних квестів**: гнучке налаштування та трекінг завдань за категоріями з можливістю швидкого перемикання статусу або точного введення прогресу.
- **Двигун досвіду (XP Engine)**: алгоритмічний розрахунок нагород, прогресивні множники за перевиконання норм та динамічні пороги переходу між рівнями.
- **Механізм добового скидання та штрафів**: щоденний контроль виконання з автоматичним збільшенням складності невиконаних завдань.
- **Система досягнень**: масштабована сітка досягнень із градацією рангів від E до S.
- **Аналітика та інтеграція показників здоров'я**: збереження історії метрик, інтеграція з Health Connect та побудова інтерактивних графіків.
- **Фоновий планувальник (WorkManager)**: регламентні завдання для нічного перерахунку стану та відправки системних сповіщень.

---

## 2. Функціональні характеристики

### 2.1. Керування квестами
Додаток підтримує роботу з чотирма категоріями активностей:
- `physical` — фізичні тренування (інтегровано вбудований довідник вправ `QuestExercises`);
- `mental` — інтелектуальна діяльність та читання літератури (облік сторінок);
- `coding` — програмна інженерія та розробка (облік часу або обсягу завдань);
- `languages` — вивчення іноземних мов (облік занять або вправ).

**Взаємодія з інтерфейсом квесту:**
- **Коротке натискання (Click)**: миттєва інверсія статусу виконання (`isCompleted = true/false`) зі встановленням поточного значення прогресу на рівень цілі або 0 відповідно.
- **Тривале натискання (Long Click)**: виклик модального вікна для введення точного кількісного показника прогресу.

### 2.2. Розрахунок досвіду та рівнів

| Подія | Алгоритм розрахунку досвіду |
|---|---|
| Виконання стандартного квесту | `expReward` |
| Виконання штрафного квесту | `expReward * 1.5` |
| Перевиконання цілі (`progress > target`) | `(overshot * (expReward / target)) * multiplier` |
| Зниження прогресу нижче цілі | Пропорційне списання раніше нарахованого досвіду |

**Коефіцієнт прогресивного бонусу за перевиконання:**
```
multiplier = 1.0 + (currentLevel / 10) * 0.01
```
- Рівні 0–9: x1.00 (базовий)
- Рівень 20: x1.02
- Рівень 100: x1.10
- Рівень 200: x1.20

**Поріг переходу на наступний рівень:**
```
xpToNextLevel = 100 + 10 * currentLevel
```

### 2.3. Алгоритм щоденного скидання (Daily Reset)
Процедура перевірки та скидання стану виконується об'єктом `DailyResetManager` при старті застосунку або за розкладом фонової задачі `MidnightResetWorker`:
1. Якщо дата останнього скидання (`lastResetDate`) збігається з поточною датою, операція пропускається.
2. При первинній ініціалізації (`lastResetDate` порожній) встановлюється поточна дата без застосування штрафних санкцій.
3. Якщо дата змінилася:
   - **Усі квести виконані**:
     - Прогрес скидається до 0.
     - Цілі квестів повертаються до вихідних значень (`originalTarget`).
     - Прапорець штрафу `isPenalty` знімається (`false`).
     - Інкрементується прогрес досягнення "Гравці в реальне життя" (`players_irl`).
     - Прапорець `hadPenaltyYesterday` встановлюється у значення `false`.
   - **Є невиконані квести**:
     - Для невиконаних квестів, які ще не мали статусу штрафу, цільове значення збільшується на 50%: `target = max((originalTarget * 1.5).toInt(), originalTarget + 1)`.
     - Встановлюються ознаки `isPenalty = true` та `progress = 0`.
     - Для виконаних квестів прогрес обнуляється зі збереженням їхніх базових параметрів.
     - Прапорець `hadPenaltyYesterday` у профілі користувача встановлюється у значення `true`.

### 2.4. Система досягнень
Досягнення підтримують шестирівневу шкалу рангів: **E -> D -> C -> B -> A -> S**.

| Назва | Ідентифікатор | Відстежувана метрика |
|---|---|---|
| Архітектор Системи | `system_architect` | Кількість днів програмування |
| Бібліотека Монарха | `monarch_library` | Загальна кількість прочитаних сторінок |
| Лінгвістичний Поліглот | `polyglot` | Кількість днів вивчення мов |
| Шлях до Олімпу | `road_to_olympus` | Кількість виконаних тренувальних підходів |
| Гравці в реальне життя | `players_irl` | Кількість ідеальних днів (усі квести виконані) |

**Пороги переходів між рангами:**
- Ранг E: 10
- Ранг D: 50
- Ранг C: 100
- Ранг B: 500
- Ранг A: 1 000
- Ранг S: 10 000

### 2.5. Регламентні фонові задачі та сповіщення
Фонова робота реалізована через `androidx.work.WorkManager` із періодичністю 24 години:
- **`MidnightResetWorker`** (старт о 00:00): виконує автоматичне добове скидання квестів у часовому інтервалі з 00:00 до 05:59.
- **`MorningNotifyWorker`** (старт о 08:00):
  - Якщо активовано штраф (`hadPenaltyYesterday == true`), надсилає системне попередження про штрафний статус та збільшення цілей на 50%.
  - За відсутності штрафу відправляє ранкове інформаційне повідомлення про оновлені квести.
- **`EveningReminderWorker`** (старт о 19:00):
  - Аналізує стан квестів. Якщо залишилися незавершені задачі, формує нагадування про необхідність їх закриття до кінця доби для уникнення штрафу.

*Примітка: відправка сповіщень контролюється параметром користувача `isSoundEnabled`.*

## 3. Архітектура додатку

Проект організовано відповідно до принципів Clean Architecture із розподілом за функціональними рівнями:

```
app/src/main/java/ua/zxcode/sololevelingapp/
├── core/
│   ├── health/                # Інтеграція з Health Connect API
│   ├── navigation/            # Маршрутизація екранів (Jetpack Compose Navigation)
│   └── work/                  # Робочі класи WorkManager та менеджер добового скидання
├── data/
│   ├── local/
│   │   ├── dao/               # Room Data Access Objects (User, Quest, Stat, Achievement)
│   │   ├── db/                # Конфігурація AppDatabase та міграції схеми
│   │   └── entity/            # Сутності бази даних SQLite
│   └── repository/            # Інтерфейси репозиторіїв та їх реалізації в repository/impl
├── di/                        # Hilt-модулі впровадження залежностей (Database, Repositories)
├── presentation/
│   ├── achievements/          # UI-компоненти екрану досягнень та розрахунок рангів
│   ├── components/            # Базові спільні елементи інтерфейсу
│   ├── home/                  # Головний екран, оверлеї профілю, налаштування квестів та вправ
│   └── stats/                 # Візуалізація статистики та графіків активності
└── ui/                        # Тематизація, кольорові схеми та типографіка
```

## 4. Схема бази даних

Керування локальними даними здійснюється через **Room 2.8.4** (SQLite). Поточна версія схеми бази даних: **5**.

### 4.1. Таблиця `user`
Зберігає стан профілю користувача. Завжди містить один запис із фіксованим первинним ключем.

| Колонка | Тип | Обмеження | Опис |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY | Фіксований ідентифікатор (значення: 1) |
| `nickname` | TEXT | NOT NULL | Ім'я профілю користувача |
| `currentLevel` | INTEGER | NOT NULL | Поточний рівень |
| `currentXp` | INTEGER | NOT NULL | Поточний накопичений досвід |
| `xpToNextLevel` | INTEGER | NOT NULL | Загальна кількість досвіду для наступного рівня |
| `gender` | TEXT | NOT NULL | Стать |
| `birthDate` | TEXT | NOT NULL | Дата народження |
| `isSoundEnabled` | INTEGER (Boolean) | NOT NULL | Стан системних сповіщень (активні / неактивні) |
| `lastResetDate` | TEXT | NOT NULL | Дата останнього виконаного скидання у форматі `yyyy-MM-dd` |
| `hadPenaltyYesterday` | INTEGER (Boolean) | NOT NULL | Ознака отримання штрафу за попередню добу |

### 4.2. Таблиця `quests`
Зберігає конфігурацію та стан виконання щоденних задач.

| Колонка | Тип | Обмеження | Опис |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Унікальний ідентифікатор задачі |
| `title` | TEXT | NOT NULL | Назва квесту |
| `expReward` | INTEGER | NOT NULL | Базова нагорода досвіду |
| `isCompleted` | INTEGER (Boolean) | NOT NULL | Статус виконання |
| `category` | TEXT | NOT NULL | Категорія (`physical`, `mental`, `coding`, `languages`) |
| `progress` | INTEGER | NOT NULL | Поточний прогрес виконання |
| `target` | INTEGER | NOT NULL | Актуальна ціль (з урахуванням можливого штрафу) |
| `isPenalty` | INTEGER (Boolean) | NOT NULL | Ознака штрафного квесту |
| `originalTarget` | INTEGER | NOT NULL | Базове цільове значення до застосування штрафів |

### 4.3. Таблиця `achievements`
Зберігає стан прогресу та ранги системи досягнень.

| Колонка | Тип | Обмеження | Опис |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | Постійний рядковий ідентифікатор досягнення |
| `title` | TEXT | NOT NULL | Назва досягнення |
| `iconResId` | INTEGER | NOT NULL | Ідентифікатор ресурсу піктограми |
| `currentRank` | INTEGER | NOT NULL | Індекс рангу (-1: не розпочато, 0: E, ..., 5: S) |
| `progress` | INTEGER (Long) | NOT NULL | Абсолютний накопичений прогрес |
| `isCompleted` | INTEGER (Boolean) | NOT NULL | Ознака досягнення максимального рангу S |

### 4.4. Таблиці `stats` та `stat_records`
- **`stats`**: метадані відстежуваних показників (`id`, `title`, `iconResId`, `lastValue`).
- **`stat_records`**: часові зрізи метрик (`recordId`, `statId`, `value`, `timestamp`). Таблиця містить зовнішній ключ на `stats(id)` із правилом `ON DELETE CASCADE` та індексом по стовпцю `statId`.

### 4.5. Історія міграцій
- **Версія 4 -> 5**: додано стовпці `lastResetDate TEXT NOT NULL DEFAULT ''` та `hadPenaltyYesterday INTEGER NOT NULL DEFAULT 0` до таблиці `user`.

## 6. Інструкція зі складання та запуску

### 6.1. Системні вимоги
- Android Studio Meerkat, Ladybug або новіша версія
- Java Development Kit (JDK): версія 17 або 21
- Android SDK Platform 36
- Фізичний пристрій або емулятор з операційною системою Android 16 (API Level 36) або вище

### 6.2. Кроки розгортання
1. Клонувати вихідний код репозиторію:
   ```bash
   git clone https://github.com/your-username/SoloLevelingApp.git
   cd SoloLevelingApp
   ```
2. Відкрити проект у середовищі Android Studio.
3. Дочекатися завершення синхронізації проекту з файлами Gradle.
4. Зібрати налагоджувальну версію застосунку (Debug APK):
   ```bash
   ./gradlew assembleDebug
   ```
   Згенерований інсталяційний пакет буде розміщено за шляхом:
   `app/build/outputs/apk/debug/app-debug.apk`
5. Запустити додаток на підключеному пристрої через інтерфейс Android Studio або за допомогою ADB:
   ```bash
   adb install app/build/outputs/apk/debug/app-debug.apk
   ```
